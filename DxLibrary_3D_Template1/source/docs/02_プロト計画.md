# プロトタイプ計画

## 目的（企画書のゲート）
1. 合成なしでも1部屋の戦闘が成立する（移動・回避・通常攻撃・カードで気持ちよく戦える）
2. 合成・進化が「使うと有利」かつ AI方策でも使われる（数値で確認）
3. 画面を別モデルに見せて「何が起きているか分かる・合成をやりたくなる」と評価される

## スコープ
- 部屋：1つのアリーナ（640×360論理座標・2倍表示、外周壁＋柱2〜4本）、3ウェーブ
- プレイヤー：移動・ダッシュ・通常攻撃（短射程の魔力弾）・HP 100
- カード 12種（各属性3＋無2）、ランク★1〜3、各1進化（計24定義）
- 合成：同名ランクアップ／異種「左の型＋右の属性」・反応10種
- 状態異常：燃焼・凍結・感電・重圧、粉砕、倍率上限
- 敵 4種：スライム（追跡）／アーチャー（距離を取り射撃）／突進兵（溜め→突進）／術師（円形弾幕）
- HUD：HP、マナ、手札4枚＋ペア間の合成プレビュー、熟練度ゲージ、山札/捨て札枚数
- 仮素材：図形（円・矩形）＋属性色。Effekseerは1種だけ組み込み確認（爆発）
- 自動検証：ヘッドレスシミュレータ（DxLibを使わない別exe）、スクリプト入力、スクショ自動保存

## アーキテクチャ
```
src/
  core/   Vec2, Rng(シード付き), Input(抽象: InputState 構造体), Log
  game/   ← DxLib非依存（ヘッドレスexeでも同じコードを使う）
    CardDefs.*     カード定義テーブル（データ駆動: 型・属性・威力・コスト・熟練度上限・進化先）
    Card.*         CardInstance（定義ID・ランク・属性[2]・熟練度・合成フラグ・素材記録）
    Deck.*         山札/手札/捨て札・自動補充・定着
    Fusion.*       合成ルール（プレビュー生成もここ。描画はこの結果を表示するだけ）
    World.*        エンティティ（Player, Enemy, Projectile, Zone, Turret）、衝突、ウェーブ
    Combat.*       ダメージ計算・状態異常・反応・倍率上限
    Enemies.*      敵AI
    Events.*       ゲーム→描画への一方向イベント列（ヒット・撃破・合成・進化・カード使用）
  sim/    Policy（AI方策: 無合成 / 合成あり / 人間相当） + ヘッドレスmain（SimMain.cpp）
  app/    ← DxLib依存
    main.cpp, Renderer, Hud, Particles, Fx(Effekseerラッパ), Audio(仮), InputDx(キーボード/マウス/パッド→InputState), Capture(スクショ)
```
- ゲームロジックは `World::update(const InputState&)` を 1/60秒固定で呼ぶだけ。乱数はWorldが持つシードRNGのみ
- 描画は World の状態と Events を読むだけ（状態を変更しない）
- build.bat：`CardForge.exe`（app+game+core）と `CardForgeSim.exe`（sim+game+core、コンソール）の2ターゲット
- スクリプト入力：`--script file.txt`（フレーム番号とキー操作の列）、`--shots N`（Nフレームごとに PNG 保存）、`--autoplay policy`（AI方策でプレイ＝描画あり）

## 計測（ヘッドレス、各方策 50シード）
- 部屋クリア時間（目標 30〜75秒 ＝ 1800〜4500F）、被ダメ、死亡率
- 方策比較：「カードのみ（合成なし）」vs「合成あり」vs「合成＋進化」→ 合成ありの方が被ダメ・時間で 15% 以上有利であること
- 1部屋あたり合成回数・進化回数

## 作業順
1. core（Vec2, Rng, InputState）、World骨格、プレイヤー移動・ダッシュ・通常攻撃、敵1種 → ヘッドレス/描画の両方で動作確認
2. カード定義・デッキ・手札・マナ・カード使用（12種の効果）
3. 状態異常・反応・合成・プレビュー・進化
4. 敵4種・ウェーブ・勝敗
5. HUD・Particles・ヒットストップ・揺れ・Effekseer1種
6. AI方策・ヘッドレス計測・スクショ評価 → 調整
7. プロト成果レビュー（別モデル：コード＋スクショ＋計測値）

## レビュー反映後の確定仕様（本文より優先）
### 入力（左手は移動専用＋近いキーのみ）
| 操作 | KB+M | パッド |
|---|---|---|
| 移動/照準/通常攻撃 | WASD / マウス / 左クリック | 左/右スティック / RT |
| ダッシュ | Space または Shift | A |
| 選択カーソル移動 | マウスホイール / 1〜4キーで直接選択しない（下記） | LB / RB |
| 選択中カードを使う | 右クリック | X |
| 直接使用 | 1〜4（使い慣れた人向け） | — |
| 合成（選択中＋右隣。右端選択時は左隣＋右端） | Q | Y |
| 進化（選択中） | E | B |
- カーソルは手札の1枚を指し、合成プレビューは「カーソルのペア」を大きく、他ペアは小さく常時表示

### 合成の決定表
- CardInstance = { defId, rank(1-3), elem[2](無=None), power(計算済み値), cost, mastery, fused, materials(基本カードのフラットリスト、最大4) }
- **ランクアップ**：両方が未合成・同defId・同ランク・ランク<3 → rank+1（威力はdef基準×ランク倍率で再計算）、熟練度は大きい方
- **異種合成**（上記以外すべて）：
  - 型・挙動 = 左のdef（進化済みなら進化後def）
  - 属性：L.elem[0] と R.elem[0] から「無」を除き重複を除いたもの。2つ→その2属性の反応、1つ→同属性なら「純化」、片方が無なら「共鳴」、0→「共鳴（無）」
  - 威力 = (L.power + R.power) × 0.7（共鳴は ×1.3 を追加）、コスト = min(4, max(L.cost, R.cost)+1)
  - 熟練度 = min(上限, (L+R)×0.5)、合成済みカードはランクアップ不可
  - materials 合計 > 4 なら **合成不可**（プレビュー灰色「これ以上は不安定」）
- 部屋終了時：fused カードは materials に分解。定着を選んだ1枚のみ維持
- 倍率の適用順：基本威力(ランク込) → 合成 → 状態異常倍率（粉砕×2.5など）→ **状態異常系倍率の合計上限 ×3.0**
- 起動時に全組合せ（全def×ランク×属性）総当たりテストを実行し、威力0・コスト範囲外・属性重複が0件であることを確認

### 決定性・エンティティ
- エンティティは型ごとの `std::vector`＋`alive`フラグ、更新中の追加は pending に積みフレーム末に合流・死亡は末尾で除去
- 更新順固定：入力→プレイヤー→カード処理→敵→弾→ゾーン/設置物→衝突→死亡処理→ウェーブ→イベント
- 乱数：ゲーム用 `World::rng` と見た目用 `fxRng` を分離。方策は自前RNG
- `/fp:precise`、状態ハッシュを 60F ごとに記録し、同一シード＋同一入力で Debug/Release 一致を自動テスト
- ヒットストップは World 内カウンタ（その間は全ロジック停止、入力はバッファ）。時間計測は総フレーム
- Run（デッキ・HP・ゴールド・レリック＝永続）と Room（戦闘）を最初から別クラス

### カード効果
- 「型」5種（弾/範囲/近接/設置/防御）の挙動をコードで持ち、カードはパラメータ（威力・弾数・拡散・速度・半径・持続・状態付与量）のデータ。合成はパラメータ変換
- データは `data/cards.tsv`（起動時読込、F5でホットリロード）

### 反応の検証区分
- 実装・計測対象：爆雷・溶岩・超伝導・永久凍土・磁砂・純化・共鳴・粉砕
- 簡易：蒸気（敵の射撃間隔+40%・弾速-30%に置換）
- 敵パラメータ：凍結耐性・ノックバック耐性・弱点属性（突進兵＝土に弱い、術師＝雷に弱い、スライム＝火に弱い、アーチャー＝氷に弱い）

### 計測（ゲート②の改訂）
- 方策：Random（合法手ランダム）／Greedy-NoFuse／Greedy-Fuse（その時点の期待ダメ/マナで合成と単独使用を比較して選ぶ）／Greedy-Fuse+Evo
- 人間相当パラメータ skill 0.3/0.6/0.9（反応遅延20/14/8F、照準誤差、回避入力の成功率）
- 出力：シード別CSV（クリアF・被ダメ・合成/進化回数・死亡・タイムアウト）、中央値/P10/P90、勝率差の95%CI
- 合格：Greedy-Fuse が Greedy-NoFuse に対し被ダメ or 時間で有意に有利（CIが0をまたがない）、skill0.6 の部屋死亡率 10〜30%、Greedy-NoFuseでも死亡率 50%未満（ゲート①）
- 期待値記録：合成を選んだ瞬間の「合成カード威力/マナ」と「素材個別使用の威力/マナ」の差

### ゲート③の改訂
- 「UIの読み取りやすさ」に限定。スクショを別モデルに見せ、チェックリスト（手札枚数・カーソル位置・合成結果名・HP/マナ・敵弾位置・進化可能カード）の正答率 80%以上
- 操作性は入力設計（左手が移動と衝突しない）で担保し、αで再評価

### 追加するもの
- F1 デバッグオーバーレイ（当たり判定・AI状態・数値）、R リスタート、P ポーズ、非アクティブ時停止
- スクリプト入力形式：`frame keys mouseX mouseY buttons`（押下中キー列を毎行記述、変化行のみ）
- 仮SE：DxLib の MakeSoftSound で波形生成（ヒット・撃破・カード・合成・進化）
- 作業順に **ゲート①中間チェック**（手順2の後、合成実装前にヘッドレス計測）
- 固定1画面（スクロールなし）、640×360 のオフスクリーンに描画して Nearest で 2倍拡大

## リスクと対策
- 合成操作が分かりにくい → プレビューを大きく、合成可能ペアは光らせる。評価で失敗なら「スロット選択→合成ボタン」方式を試作
- 進化2分岐の操作 → プロトでは1分岐のみ。2分岐の方式はαで決定
- C++のビルド時間 → ファイル分割、/MP、ヘッダ最小化
