# UI 修正計画（v1.0.1）

## 背景
v1.0.0 を利用者が実際に遊び、次の不具合が見つかった。
- 拠点（Hub）の説明文が画像と重なって読めない
- フルスクリーンにするとマウスカーソルが消える

原因は検査の穴。
- 自動操作は拠点をすぐ抜けるため、β以降の撮影に拠点が1枚も入っていなかった
- フルスクリーンは一度も試していない
- スクリーンショットは縮小した一覧（1コマ240px）で見ており、文字の重なりを判別できなかった
- 別モデルのレビューには、私が選んだ7枚しか渡していなかった
- 人の操作（マウス・キーボード・パッド）による確認がなかった

## 判明している原因（別モデルの計画レビューで特定、コードで確認済み）
- **拠点**：解放カードは10枚で、1行8枚のため2段になる。フォーカス中の説明パネル `panel(80, 360, 1120, 70)` が2段目のカード（y=355〜）と「試練」見出し（y=460付近）に重なる。さらに当たり判定は高さ150、描画は高さ120で、見た目と押せる範囲がずれている
- **カーソル**：`SetMouseDispFlag(TRUE)` を起動時にもモード切替後にも呼んでいない。DxLib はフルスクリーンで既定でカーソルを隠すため、戦闘外の画面ではずっと消える。戦闘終了時とポーズ中にだけ TRUE にしているので、たまたま見える場面がある
- **マウス座標**：`InputDx.cpp` で座標を一律 0.5 倍している（論理 640x360 前提）。ウィンドウのサイズ変更やフルスクリーンで、`GetMousePoint` が 1280x720 基準の値を返すかは未確認

## 方針
「そのとき直していた画面」ではなく、**コードの列挙型（Screen・Phase・Pick）と全描画関数から画面・状態を機械的に列挙して、等倍で撮り、別モデルが私の選別を通さずに全数を検査する**。目視に加え、文字のはみ出しと矩形の重なりは**コードで自動検出**する。

## 手順
### 1. ギャラリーモードの実装（`--gallery`）
状態を直接組み立てて各画面を表示し、1280x720 の等倍で PNG を保存する。撮影リストは列挙型から生成し、漏れがあれば実行時に失敗させる。

| 区分 | 撮影する状態 |
|---|---|
| Screen：Title | 続きなし / 続きあり / 新規開始の確認ダイアログ（タイトル経由と拠点経由の2経路）/ プロフィール破損のトースト |
| Screen：Hub | 解放0 / 一部解放 / 全解放 / **10枚すべてに順にフォーカス** / 魂片 不足・十分 / 難易度 やさしい・ふつう・試練5 / トースト表示中 |
| Screen：Options | 全設定の ON/OFF、音量 0 と最大、戦闘のポーズから来た場合（戻り先が戦闘） |
| Screen：Keys | 待機中 / 入力待ち / 長いキー名 |
| Screen：Credits | 先頭・途中・末尾 |
| Screen：Result | 勝利 / 敗北 |
| Screen：Tutorial | 8ステップすべて / ポーズ / 完了 |
| Phase：Map | 第1〜3章 / 各ノード種別にフォーカス / ヒント表示中 |
| Phase：Battle | 通常・エリート・ボス3体 / ポーズ / 手札空・満杯 / 長い名前の合成カード / 進化可能 / 反応表示 / ヒント表示中 / **キーボード表示とパッド表示の両方** |
| Phase：Reward | カードのみ / カード＋レリック / 長い名前のカード / ヒント表示中 |
| Phase：Shop | 通常 / 売り切れ / 所持金不足 / ヒント表示中 |
| Phase：Forge・Rest・Event | 全状態。イベントは8種すべて、選べない選択肢を含む |
| Phase：ChapterClear・Victory・Defeat | 全章 |
| Pick（9種：Remove, Anchor1, Anchor2, RankUp1, RankUp2, Train, RestTrain, Upgrade, View） | それぞれ 少数（5枚）と多数（30枚以上、スクロール） |
| 共通オーバーレイ | ヒント帯とトーストを、全画面それぞれに重ねた状態。長い文言も試す |
| 上部バー | レリック0個 / 20個（あふれ） |

対象外（理由を明記）：起動失敗・クラッシュ時の MessageBox（OS の描画）、F1 のデバッグ表示（開発版のみ）。

### 2. コードによる自動検出（ギャラリー実行中）
- **文字のはみ出し**：描画する全文字列について、文字列の幅と、収めるべき箱（ボタン・パネル・カード）の幅を比べ、はみ出しを記録する
- **矩形の重なり**：その画面で描いたボタン（`ui.add`）、パネル、文字の矩形を集め、重なってはいけない組み合わせの交差を記録する
- **当たり判定と見た目のずれ**：`ui.add` の矩形と、実際に描いたボタン・カードの矩形が一致しないものを記録する
- **小さすぎる文字**：画面上 12px 未満の文字、背景とのコントラストが低い文字を記録する
- 記録は `gallery_report.txt` に出し、1件でもあれば不合格

### 3. カーソルと表示モード
**設計の修正**：カーソルの表示は「画面状態の関数」として毎フレーム1か所で決める。戦闘中（ポーズ以外）でマウスを使っていないときだけ隠し、それ以外は必ず表示する。起動時と画面モードの切り替え直後にも再設定する。

**検証**：Win32 の `GetCursorInfo`（`CURSOR_SHOWING` と `hCursor` が NULL でないこと）を、画面遷移ごと・モード切替直後の数フレームに記録し、期待値と比べる。
- 起動時フルスクリーン（設定から）、F11 の往復と連打、オプションからの切り替え、ポーズ中の切り替え、Alt+Tab の往復
- 切り替えのたびに、設定値と実際の画面モードが一致するか

**マウス座標の実測**：テスト中だけ `SetCursorPos` でカーソルを既知の位置へ動かし、論理座標への変換と当たり判定が正しいかを記録する。対象はウィンドウ（初期サイズ・拡大・縮小）とフルスクリーン。※この間、このPCのマウスカーソルが自動で動く。

**このPCで確かめられない環境**：別の解像度・縦横比（16:10、21:9、4:3）、高DPI（125%・150%）、マルチモニタ。表示設定の変更はシステム設定の変更になるので行わない。フルスクリーンの拡大方式（縦横比を保って黒帯を入れる）をコードで明示し、利用者の実機確認リストに入れる。

### 4. 別モデルによる全数検査
- **1エージェント 10〜12枚まで**。画面群ごとに分けて並列に依頼する
- 画像は**1枚ずつ等倍で開かせる**。一覧画像は渡さない
- 画像ごとに**固定のチェックリスト**に○×を書かせる：重なり / はみ出し / 切れ、文字の読みやすさ（大きさ・コントラスト）、ボタンと説明の重なり、画像の上に乗る文字、画面端の切れ、不自然な日本語、意味の伝わらない表記。「問題なし」の項目にも、確認した領域を書かせる
- **カナリア**：修正前の拠点の画像（既知の不具合）を、どれか1グループに知らせずに混ぜ、検出できるかを確かめる。検出できなければその検査は無効にしてやり直す
- **二重検査**：全画像の約20%を別のエージェントにも検査させ、見落とし率を測る
- 自動検出（手順2）の結果も渡し、画像と照合させる

### 5. 修正と再検査
- 指摘をすべて修正し、ギャラリーを撮り直す
- 撮り直した画像を、前回とは別のエージェントに同じ方式で再検査させる。重大・中がゼロになるまで繰り返す
- 回帰用に、合格したギャラリー画像を基準として保存し、以後は差分で確認する

### 6. 実際の入力経路での確認
既存の自動操作は UI を直接叩くため、キーボード・パッドの入力処理とフォーカス移動を通っていない。そこで別に次を行う。
- **フォーカスの可視化**：全画面で、全ボタンに順にフォーカスを当てて撮影する（フォーカス枠が見えるか）
- **到達性**：方向キーの入力を入力処理に直接流し込み、全ボタンへフォーカスが届くか（取り残されるボタンがないか）を自動で調べる
- **決定・キャンセル**：Enter / Space / Esc / パッドの A・B を入力処理に流し込み、全画面で想定どおり遷移するかを調べる

### 7. 記録と配布
- 成果書（`docs/09_マスタ成果.md`）の誤った記述（「全画面に表示崩れがない」）を訂正する
- v1.0.1 として配布物を作り直す（版表記、README の更新履歴）

## 終了条件
1. 撮影リスト（列挙型から生成）の全状態を、ウィンドウとフルスクリーンで撮影済み
2. 自動検出（はみ出し・重なり・当たり判定・小さい文字）が0件
3. 別モデルの全数検査で重大・中が0件。カナリアを検出できていること
4. カーソルの表示記録とマウス座標の実測が、すべて期待どおり
5. キーボード・パッドの到達性と遷移の検査が合格
6. 自動操作の QA（30本）で回帰なし
7. **利用者による実機確認**（このPCで確認できない項目のチェックリストを渡す）

## 計画レビューの補足（実行前に反映）
- 判定：「このまま実行してよい」（必須7項目すべて反映を確認済み）
- カナリア画像は、拠点を直す**前**にギャラリーで撮って保存する
- ギャラリーは本番と同じ描画関数（doHub など）を通す。ギャラリー専用の描画コードは作らない
- マウス座標の変換を純関数にし（ウィンドウサイズ・画面サイズ・黒帯 → 論理座標）、16:10、21:9、4:3 は単体テストで検証する
- exe の DPI 対応設定（マニフェスト）を静的に確認する
- フルスクリーンが解像度を切り替える方式か、デスクトップ解像度のまま拡大する方式かを確認し、後者に固定する
- フルスクリーンの見た目は、OS の画面キャプチャでも最低1枚撮る
- 利用者の実機確認リストは具体的に書く（解像度・縦横比、DPI、副モニタ、Alt+Tab、カーソル、クリック位置）

### 画面モード切替時のクラッシュ（原因を特定して修正）
- 症状：F11／オプションで画面モードを切り替えたとき、まれに d3d11.dll 内で 0xC0000005 で落ちる（ギャラリー実行中に計4回）
- 再現：画面モード切替だけを繰り返す QA モード `--modestress N` を追加（タイトル→新しい戦闘→一時停止→F11 を N 回）。修正前は 40回×4本がすべて途中で落ちた。切替専用ギャラリーも 20回中12回落ちた
- 原因：クラッシュ時のコールスタックを crash.txt に書き出すようにして特定。DxLib 3.24f の ChangeWindowMode が描画環境を作り直す際、直前のバックバッファを新しいバッファへ写す処理（Graphics_D3D11_SetupSubBackBuffer → StretchRect）で d3d11 が不正アクセスしていた。エフェクト（Effekseer）を描かなくても、一時停止しなくても起きた
- 修正：切替の直前に、バックバッファを消去して一度表示してから切り替える（全ての切替を `changeDisplayMode()` に集約）
- 確認：修正後 `--modestress 40` を5本（切替 200回）クラッシュ 0、切替専用ギャラリー 20本（下の結果）、通常のギャラリー（ウィンドウ・フルスクリーン）、回帰の自動プレイ
- 途中で試した「切替前にエフェクトを止める」対策は効果がなく、かえって検査で失敗が増えたため取り消した
- クラッシュ記録（crash.txt）には今後、モジュール名と位置のコールスタックも残る（プレイヤーからの報告で原因を追える）

### 仕様・フォントの制約として受け入れた点
- 12px の補助表示（キー名など）は字形が小さい（例：「雷」が「園」に、「Q」が「O」に見えることがある）。正式な名前はパネルに 24px で出す
- タイトルの装飾リング、ボスHPバーに数値がないこと、照準の白い輪、敵が出現時のフェード中に暗く見えること
- フルスクリーン 1920x1080 は 1.5 倍の非整数拡大のため、ドットの線幅が不均一になる（整数倍＋黒帯への変更は v1.0.1 では見送り）
- 合成の結果が元のカードより威力が低く見える組み合わせがある（表示は正確。ゲームバランスの仕様）
- 用語（修練・訓練・試練、強化・ランクアップ・進化）、イベントの台詞の中の「ゴールド」（選択肢・画面表示は「G」に統一）、イベント画面の下側の空白
- 検査担当の間で判断が割れた点：無効ボタンの明るさ（暗いと「読みにくい」、明るいと「押せそう」）。暗い箱＋読める文字＋理由の表示で決着
- ギャラリーの固定状態による見え方（例：ランクアップの2枚目を最後のページから開く）は、実際の操作では起きない

### 未検証（実機での確認が必要）
- 1280x720 以外の画面比（16:10、ウルトラワイド）、高DPI（125%/150%）、複数モニタ
- 実際のゲームパッド
- 人が通しで遊ぶこと（自動プレイと静止画の検査のみ）
