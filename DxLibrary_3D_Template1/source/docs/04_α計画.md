# α計画

> **レビュー反映版（本節が以下の本文より優先）**
>
> ### 分割と順序
> - **α1 骨格**：Content化（敵/部屋/アリーナ/Modifiers）→ RoomResult → RunState＋Action（reducer）→ MapGen → RunLogic（報酬/商店/鍛冶場/休憩/イベント4種）→ Save（RunState直後に実装）→ 連続ランsim。ゲート2・5をここで通す
> - **α2 内容**：敵AI 6種追加、エリート、ボス3体、レリック15種（フック）、カード+8。ゲート3・4を計測。設計破綻はここで検出
> - **α3 外殻**：SceneManager と全画面（RunStateのphaseを描画しActionを送るだけ）、拠点とメタ解放、アセンション1のみ、図鑑は記録のみ（UIはβ）、パッド対応メニュー。スクリプト巡回でゲート1、スクショ連番の面白さ評価
> - βへ送る：アセンション2〜5、図鑑UI、イベント残り4種、呪いカードの本格運用、オプション細目、進化2分岐（MVPは単一進化に確定・企画書改訂）
>
> ### アーキテクチャ確定事項
> - `RunState.phase`（Map/Battle/Reward/Shop/Forge/Rest/Event/BossReward/ChapterClear/Victory/Defeat）と `RunLogic::apply(RunState&, const Action&)`。UI・sim方策・スクリプトが同じ Action を投げる
> - 乱数ストリーム分割：map / battle / reward / shop / event をそれぞれ `seed ^ hash(chapter, node, purpose)` から派生。**報酬や商店の中身はノード確定時に決定論的に決まる** → セーブ&ロードで再抽選不可
> - Save：ノード突入前とマップ表示時に自動保存。RunState全体のシリアライズ（文字列ID）。αの間は version 不一致なら破棄（バックアップ退避のみ）。sim で毎ノード `save→load→再シリアライズ一致` を全ランで検査
> - `RoomResult { result, hpLeft, deck（分解後）, kills, fusions, reactionsMade, goldDrop }`。World は Run を書き換えない
> - Modifiers（係数）＋ RelicHooks（onRoomStart / onFuse / onKill / onHurt / onCardUsed / onEvolve をイベント列挙で dispatch）。全15レリックの表を α2 冒頭で確定
> - 敵AIは C++ の状態機械を文字列IDで登録。ボスはプリミティブ（跳躍・リング・落下・壁・召喚・レーザー）をC++、並びとパラメータをデータで
> - 敵の生成は pending キュー経由
>
> ### 仕様確定
> - **定着カード**（鍛冶場）：使用しても素材に戻らない永続カード。進化不可、合成素材にもできない（戦闘中合成の左右どちらにも使えない）。ラン中最大3枚
> - 鍛冶場3択：定着 / ランクアップ（同名2枚→★+1、素材1枚消費）/ 修練（1枚の熟練度+4）
> - 撃破HP回復レリックは部屋あたり最大5。倍率系は加算で STATUS_MUL_CAP の外側に別上限×2.0
> - ボス戦のタイムアウト 300秒
> - 戦闘中合成の経済はプロト結論（コスト L+R−1、×0.6、熟練度なし）
>
> ### 計測とゲート（改訂）
> - 人間代理：skill に加え **見落とし率**（弾ごとに決定論的に (1−skill)×0.5 の確率で気づかない）を導入。βで実測が取れるまでの暫定
> - 「初回」＝メタ初期・アセンション0・200ラン平均
> - ゲート3：人間代理(skill0.6)のクリア率 10〜50%（βで15〜35%へ）、章別死亡がすべて非ゼロ、ボス戦の所要時間中央値 60〜150秒・ボス別死亡率 5〜35%、random 0〜10%
> - ゲート4：方策5種（賢い / 戦闘中合成なし / 鍛冶場定着なし / 合成なし / 進化なし）。「賢い」が被ダメ総量・クリア率で有意に上、かつ「合成なし」でもクリア率が「賢い」の1/2以上
> - 追加：経済ログ（総収入・支出内訳・未使用ゴールド）、未使用ゴールド中央値が総収入の25%未満。回復総量／被ダメ総量の比 0.6〜0.9。1ランの戦闘時間合計 15〜25分
> - ゲート5：全ラン全ノードの save→load 一致
>
> ### カード数
> - 基本 22（初期プール16、解放6）→ βで28（解放12）

## ゴール
仮素材のまま「タイトル → ラン（3章・ボス3体）→ 勝利/死亡 → 拠点（メタ解放）→ 次のラン」が途切れず遊べ、全システムが揃っている。

## 終了条件（ゲート）
1. UIだけで1ランを最初から最後まで遊べる（スクリプト入力による自動巡回で、全画面を通過しクラッシュ0）
2. 連続ランsim：200ラン（方策3種）でクラッシュ・進行不能0
3. 連続ランsim：人間相当方策（skill0.6）の初回クリア率が 5〜60%（β調整前の粗い範囲）、無思考（random）が 0〜10%
4. 「合成しない」方策が「賢く合成」に対し有意に劣るが、クリア率で2倍以上の差はつかない（合成は強いが必須ではない）
5. セーブ/ロード：マップ画面で終了→再開で同じ状態（ハッシュ一致）
6. 別モデルによるα成果レビューの重大以上の指摘を解消

## スコープ
### ラン構造
- 3章。各章：分岐マップ（7層×2〜4列、Slay the Spire型、シード生成）＋ボス
- ノード：戦闘 / エリート / 商店 / 鍛冶場 / イベント / 休憩 / ボス。最初の層は必ず戦闘、ボス前は必ず休憩
- 章をまたいでデッキ・HP・ゴールド・レリックを持ち越し。章クリアでHP 30%回復

### 部屋・敵（データ駆動）
- `data/enemies.tsv`：id, 名前, ai, hp, 速度, 半径, 攻撃力, 攻撃間隔, 弾速, 弱点, 耐性, 凍結耐性, ノックバック耐性, 色, 報酬
- `data/rooms.tsv`：id, 章, 種別(normal/elite/boss), アリーナ, ウェーブ列（`slime*3+archer*2 | ...`）
- アリーナ（柱配置）5種
- 敵AI 10種：slime(追跡) / archer(3way) / charger(突進) / mage(リング弾) / splitter(死亡時に分裂) / bomber(接近して自爆・予告) / shield(正面の弾を防ぐ盾持ち) / sniper(長い予告線→高速弾) / summoner(小型召喚) / turret(固定・螺旋弾)
- エリート：通常敵の強化版（HP×2.2、サイズ×1.3、追加行動）＋金の縁
- ボス3体（各2フェーズ）：
  - 1章「スライムキング」：跳躍叩きつけ（着地予告）、分裂子召喚、HP50%で高速化
  - 2章「フロストリッチ」：リング弾、氷柱の予告落下、氷壁でアリーナ分断、HP50%で弾幕強化
  - 3章「アルカナゴーレム」：プレイヤーのカードの属性に応じて耐性が変わる、4方向レーザー、召喚
- 敵の生成・召喚は pending キュー経由（ループ中の追加を禁止）

### 報酬・経済
- 通常戦：ゴールド 15〜25、カード3択（スキップ可）。エリート：ゴールド30〜45＋レリック1＋カード3択（レア率UP）。ボス：レリック3択＋カード3択（レア）
- カードのレアリティ：コモン/アンコモン/レア（cards.tsv に rarity 列追加）
- 商店：カード5枚（50〜150G）、レリック2（150〜250G）、カード削除（75G、使うたび+25）、回復ポーション（HP25%、40G）
- 鍛冶場（1つ選ぶ）：①定着合成：デッキの2枚を選び永続合成（プレビュー表示、素材は消費、デッキ6枚未満不可） ②ランクアップ：同名2枚→★+1 ③修練：1枚の熟練度を満タン
- 休憩：HP30%回復 or 修練（熟練度+4）
- **部屋クリア時の定着は廃止**（プロトレビュー：毎部屋の純圧縮が暴走の原因）。戦闘中の合成は一撃の大技に専念

### レリック（15種、Modifiers とイベントフック）
例：マナ最大+1 / 合成するとマナ+1 / 部屋開始時に手札の1枚が★2 / 凍結時間+50% / 燃焼の上限+3 / 撃破でHP+1 / ダッシュCD-30% / 合成カードの威力+20% / 通常攻撃が3発に / 最大HP+20 / 進化に必要な熟練度-2 / 部屋開始時マナ満タン / シールド+10で部屋開始 / ゴールド獲得+25% / 弱点倍率+0.5

### イベント（8種、data/events.tsv）
選択肢2〜3、結果：HP±、ゴールド±、カード獲得/削除/変化、レリック、呪いカード（使えない枠埋め）

### メタ進行（拠点）
- ラン終了時に魂片（到達章・撃破数・ボス撃破から計算）
- 拠点で解放：カード（初期プール18→最大28）、レリック、アセンション1〜5（敵HP+10%、エリート増加、回復減少、ボス強化、開始HP-10）
- 図鑑：カード・反応・敵（見た／作った記録）

### セーブ
- `save/profile.txt`（メタ・設定・図鑑）と `save/run.txt`（ラン中断用、マップ画面でのみ保存）
- テキスト形式 `key=value`、カードは文字列ID＋ランク＋熟練度＋（合成済みなら素材IDリスト＋反応）
- version 行とマイグレーション関数を最初から用意。読み込み失敗時はバックアップに退避して新規

### UI画面
タイトル / 拠点 / マップ / 戦闘 / 報酬 / 商店 / 鍛冶場 / 休憩 / イベント / デッキ一覧 / ポーズ（再開・オプション・ラン放棄）/ オプション（BGM・SE音量、フルスクリーン、画面揺れ強度）/ 勝利 / 敗北（リザルト：到達・撃破・合成回数・作った反応）
- 全画面マウス・キーボード・パッドで操作可能（カーソル式メニュー共通部品）

### カード
- 基本カードを 14 → 22（β で 28）。新規：連鎖雷（雷・範囲）、氷槍（氷・弾 貫通）、溶岩溜まり（火・設置）、岩壁（土・設置）、旋風（無・近接）、吸血斬（無・近接 回復）、魔力の盾（無・防御）、流星群（火・範囲 複数地点）
- rarity 列、初期解放フラグ列

## アーキテクチャ変更（プロトレビュー項目7）
```
game/
  Content.*     EnemyDef / RoomDef / ArenaDef / RelicDef / EventDef の読込（文字列ID）
  Modifiers.h   レリック・アセンションが変える係数（World はこれを参照、constexpr を置換）
  RunState.*    Run を拡張：seed, chapter, map, nodeIndex, relics, gold, ascension, 統計
  MapGen.*      分岐マップ生成
  RunLogic.*    報酬生成、商店在庫、鍛冶場、休憩、イベント適用（純関数、sim から呼べる）
  World.*       init(run, roomDef, mods, seed)、終了時 RoomResult を返す（Run を直接書き換えない）
  Save.*        profile / run の保存・読込
sim/
  RunPolicy.*   マップ選択・報酬選択・商店・鍛冶場の方策（人間相当/無思考/合成なし）
  SimMain       --runs N で連続ラン
app/
  Scene.h, SceneManager, 各画面 Scene*.cpp、Menu（共通カーソルメニュー）
```
- World の敵生成は `pendingEnemies_` → cleanup で合流
- CardDB::get の範囲チェック、F5 リロードは開発ビルドのみ

## 作業順
1. Content/Modifiers/RoomDef 化（既存戦闘を data 駆動へ）→ sim で回帰（プロトと同等の数値）
2. RunState・MapGen・RunLogic → sim 連続ラン（マップ・報酬・商店・鍛冶場・休憩を方策で）
3. 敵AI 6種追加・エリート・ボス3体
4. レリック・イベント・メタ・アセンション
5. Save
6. app：SceneManager と全画面
7. スクリプト入力の自動巡回（UI全画面通過）
8. 計測・調整 → α成果レビュー

## リスク
- 画面数が多い → 共通メニュー部品とカード描画の再利用で実装量を抑える
- ボスのAIが複雑 → 状態機械をデータ（攻撃パターン列）で書く
- 連続ランsimの方策が弱すぎて計測が無意味 → 方策の決定ログを出し、1ランをスクショで確認
